## What Was Built

**Renderer (renderer.ts):**
- New color tokens: `radarRing`, `radarFill`, `fireModeTarget`, `fireModeTargetStroke`
- `fireModeTargetShipId` state with `setFireModeTarget()` / `getFireModeTarget()` accessors
- Radar ring drawn when `ship.radarOn = true` (ArleighBurke: 800wu, Carrier: 500wu, dashed teal circle)
- Fire mode targeting highlight rendered in `renderFrame` as red circle over target ship

**Interactions (interactions.ts):**
- `#mobile-actions` floating overlay: RADAR, FIRE, DESEL buttons (60x60px, min-width/height 44px)
- Overlay shows only when a ship is selected (`updateMobileActionsVisibility`)
- Fire mode state machine: FIRE button toggles, next canvas click on ship fires missile, empty click cancels
- Keyboard shortcuts: `R` = radar, `F` = fire mode, `Escape` = cancel fire/deselect
- `touchstart`/`touchend` prevent iOS scroll/zoom during gameplay
- `selectShipById(shipId)` public method for E2E test programmatic selection
- FIRE button visual: red border when fire mode active

**Main (main.ts):**
- `window.interactionManager` exposed for E2E debug and testing
- `stdbParam` URL routing for iPad/LAN support (Vite proxy path)

**SpaceTimeDB (spacetime.ts):**
- Fixed `toggleRadar`: positional `shipId` changed to object form `{ shipId }` matching reducer schema
- Fixed `fireMissile`: positional args changed to object form `{ shipId, targetX, targetY, targetShipId }`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] SpaceTimeDB reducers require object form, not positional arguments**
- **Found during:** Task 5 E2E verification (all 8/9 tests passed, radar test failed)
- **Issue:** `toggleRadar(shipId)` and `fireMissile(shipId, ...)` used positional args. The SpaceTimeDB JS SDK serializer (generated by `makeSerializer`) expects an object with named fields matching the reducer schema (e.g. `{ shipId: u64 }`). Positional bigint throws `TypeError: Cannot convert undefined to a BigInt`.
- **Fix:** Changed both calls to use object form: `toggleRadar({ shipId })` and `fireMissile({ shipId, targetX, targetY, targetShipId })`
- **Files modified:** `client/src/spacetime.ts`
- **Commit:** deb0de8

**2. [Rule 2 - Missing] Programmatic ship selection needed for E2E test isolation**
- **Found during:** Task 5 E2E verification — canvas click at canvas center hits wrong ship when multiple ships from previous tests overlap at (0,0)
- **Issue:** All tests spawn ships at (0,0); after 134+ ships accumulate in shared SpaceTimeDB instance, canvas click selects the first ship in iteration order, not our ship.
- **Fix:** Added `selectShipById(shipId)` public method on `InteractionManager`. Exposed `window.interactionManager` in main.ts. Updated radar test to use programmatic selection.
- **Files modified:** `client/src/interactions.ts`, `client/src/main.ts`, `client/e2e/ui_controls.spec.ts`
- **Commit:** deb0de8
